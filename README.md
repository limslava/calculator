## Функциональность

### Архитектура разделенных интерфейсов

#### 🏗️ Модульная архитектура
- **Отдельные интерфейсы для каждой роли** - изолированные файлы HTML и JavaScript
- **Главный интерфейс (index.html)** - для администратора и выбора роли
- **Интерфейс менеджера по продажам (sales-interface.html)** - специализированный для расчета ставок
- **Интерфейс менеджера по закупкам (purchaser-interface.html)** - специализированный для загрузки данных
- **Автоматическое перенаправление** - при входе пользователи автоматически направляются на соответствующий интерфейс

#### 🔐 Аутентификация и авторизация
- **Вход по email и паролю** - защищенная система входа
- **Автоматическое создание администратора** - при первом запуске создается администратор с данными: `admin@logistics.com` / `admin123`
- **Ролевая модель доступа** - три уровня доступа: Администратор, Менеджер по закупу, Менеджер по продажам
- **Хеширование паролей** - защита пользовательских данных
- **Смена пароля** - пользователи могут менять пароль через специальную ссылку
- **Безопасная ссылка для смены пароля** - автоматически генерируется при создании пользователя
- **Восстановление администратора** - специальная страница для восстановления роли администратора

#### 👑 Администратор
- **Управление пользователями** - создание, блокировка, удаление пользователей
- **Генерация паролей** - автоматическая генерация безопасных паролей
- **Отправка данных для входа** - отправка email с логином и паролем
- **Просмотр всех ролей** - доступ ко всем функциям системы
- **Работа в главном интерфейсе (index.html)** - доступ ко всем модулям

#### Роли пользователей
- **Администратор** - полный доступ ко всем функциям системы через главный интерфейс
- **Закупщик** - загрузка базы данных из Excel файлов и управление тарифными ставками через отдельный интерфейс
- **Менеджер по продажам** - расчет ставок для клиентов через отдельный интерфейс

#### 🔄 Навигация и кнопки управления
- **Кнопка "Назад"** - возврат к предыдущему экрану в рамках текущего интерфейса
- **Кнопка "Выйти"** - выход из системы и возврат к форме входа
- **Динамическое управление кнопками** - отображение соответствующих кнопок в зависимости от контекста
- **Раздельные интерфейсы** - каждая роль имеет свой специализированный интерфейс с оптимизированной навигацией

#### 🔐 Система смены пароля
- **Безопасная ссылка** - автоматически генерируется при создании пользователя
- **Форма смены пароля** - доступна по специальной ссылке с параметрами URL
- **Валидация пароля** - проверка совпадения нового пароля и подтверждения
- **Минимальная длина** - пароль должен содержать минимум 6 символов
- **Автоматический переход** - после успешной смены пароля автоматически возвращает к форме входа
- **Пример ссылки**: `http://localhost:3000?action=change-password&email=user@example.com`

### Типы перевозок
1. **Морские перевозки** - расчет ставок для морских контейнерных перевозок
2. **Железнодорожные перевозки** - расчет ставок для ЖД перевозок
3. **Прямые ЖД перевозки** - расчет ставок для прямых железнодорожных перевозок
4. **Прямые морские перевозки** - расчет ставок для прямых морских перевозок
5. **Море + ЖД** - комбинированные перевозки
6. **Тарифные ставки** - управление дополнительными тарифами (только для закупщика)

### Основные возможности
- Загрузка данных из Excel файлов
- Автоматический расчет ставок при заполнении полей
- Каскадная фильтрация данных
- Автопоиск и подсказки в выпадающих списках
- Сортировка результатов от меньшей к большей ставке
- **Модальное окно для расчета маржинальности** - двойной клик по результату
- Расчет комплексных ставок "Море + ЖД" с правилами соединения
- **Тарифные ставки** - управление дополнительными тарифами (ВТТ, ПРР, Автовывоз)
- **Триггер ВТТ** - автоматическое добавление стоимости ВТТ к комплексным ставкам
- Автоматическая конвертация валют (USD/RUB) по курсу ЦБ РФ
- Адаптивный дизайн для мобильных устройств
- Хранение данных в localStorage

## Тарифные ставки и ВТТ

### Управление тарифами (только для закупщика)
- **ВТТ** - стоимость ВТТ в российских рублях
- **ПРР 20** - стоимость ПРР для 20-футовых контейнеров
- **ПРР 40** - стоимость ПРР для 40-футовых контейнеров
- **Автовывоз 20** - стоимость автовывоза для 20-футовых контейнеров
- **Автовывоз 40** - стоимость автовывоза для 40-футовых контейнеров

### Триггер ВТТ в комплексных ставках
- **Активация**: чекбокс "ВТТ (море POD = жд агент)" в комплексном расчете
- **Условия**: автоматически добавляет стоимость ВТТ к комплексным ставкам Море+ЖД
- **Логика**: применяется только при совпадении "море POD = жд агент" и "Тыловой Терминал = нет"
- **Отображение**: ВТТ отображается как отдельная позиция в модальных окнах себестоимости и накрутки

## Модальное окно для расчета маржинальности

### Функциональность
- **Открытие**: двойной клик по любой строке в результатах расчета
- **Себестоимость**: отображает базовую ставку в зависимости от типа перевозки
- **Накрутка**: поля для ввода накрутки в соответствующей валюте
- **Результат**: итоговые ставки с накруткой (без отображения самой накрутки)
- **Копирование**: кнопка для копирования результатов в буфер обмена
- **ВТТ**: отображается как отдельная позиция при включенном триггере ВТТ

### Типы перевозок в модальном окне

#### Прямое море / Море
- **Себестоимость**: "Стоимость фрахта"
- **Накрутка**: поле для ввода в USD
- **Результат**: "Стоимость фрахта с накруткой"

#### Прямое ЖД / ЖД
- **Себестоимость**: "Стоимость ЖД перевозки"
- **Накрутка**: поле для ввода в USD/RUB
- **Результат**: "Стоимость ЖД перевозки с накруткой"

#### Море + ЖД (комплексные ставки)
- **Себестоимость**: "Стоимость фрахта" и "Стоимость ЖД перевозки" и "Общая стоимость"
- **Накрутка**: отдельные поля для моря (USD) и ЖД (RUB)
- **Результат**: "Стоимость фрахта с накруткой", "Стоимость ЖД перевозки с накруткой" и "Общая стоимость с накруткой"

## Технологии

- **Frontend**: HTML5, CSS3, JavaScript (ES6+)
- **Backend**: Node.js, Express.js
- **Библиотеки**: XLSX.js для работы с Excel файлах, nodemailer для email рассылки
- **Стили**: CSS Grid, Flexbox, адаптивный дизайн
- **Хранение данных**: localStorage (клиент) + JSON файлы (сервер)
- **Аутентификация**: собственная система с хешированием паролей и ролевой моделью
- **Email рассылка**: SMTP с поддержкой Gmail, Yandex, Mail.ru и других провайдеров

## Установка и запуск

### Локальная разработка
```bash
npm install
npm start
```

Приложение будет доступно по адресу: http://localhost:3000

### Первый запуск
1. Откройте приложение в браузере: `http://localhost:3000`
2. Войдите с данными администратора: `admin@logistics.com` / `admin123`
3. Создайте пользователей через панель администратора
4. Отправьте данные для входа пользователям
5. Пользователи будут автоматически перенаправляться на соответствующие интерфейсы:
   - **Менеджер по продажам** → `sales-interface.html`
   - **Менеджер по закупкам** → `purchaser-interface.html`
   - **Администратор** → остается в главном интерфейсе `index.html`

### Docker
```bash
docker build -t logistics-calculator .
docker run -p 3000:3000 logistics-calculator
```

## Развертывание на Amvera

Проект полностью готов к развертыванию на платформе Amvera через GitHub:

### Быстрый старт
1. Отправьте код в GitHub репозиторий
2. Создайте проект на [Amvera](https://cloud.amvera.ru)
3. Выберите "Из Git репозитория"
4. Укажите URL вашего репозитория
5. Amvera автоматически развернет приложение

### Подробные инструкции
Смотрите [README_AMVERA.md](README_AMVERA.md) для полного руководства по развертыванию.

### Автоматическое развертывание
При пуше в ветку `main` GitHub Actions автоматически:
- Собирает и тестирует Docker образ
- Проверяет работоспособность приложения
- Готовит приложение к развертыванию

После развертывания приложение будет доступно по адресу: `https://[имя-проекта].amvera.io`
