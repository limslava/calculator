# 🚢 Система расчета логистических ставок

Профессиональная система для управления логистическими ставками, расчета стоимости перевозок и управления пользователями.

## 📋 О проекте

Система предназначена для автоматизации расчета стоимости логистических перевозок с поддержкой различных типов транспорта:
- **Морские перевозки** (прямые и комплексные)
- **Железнодорожные перевозки** (прямые и комплексные)
- **Комплексные перевозки** (море + железная дорога)

## 🚀 Быстрый старт

### Предварительные требования
- Node.js 16+
- PostgreSQL 12+
- Созданная база данных PostgreSQL

### Настройка базы данных
1. Создайте базу данных PostgreSQL
2. Настройте переменные окружения в файле `.env`:
```bash
DATABASE_URL=postgresql://username:password@localhost:5432/database_name
JWT_SECRET=your-secret-key-change-in-production
```

### Установка зависимостей
```bash
npm install
```

### Запуск сервера
```bash
npm start
```

### Доступ к приложению
Откройте в браузере: `http://localhost:3000`

### Данные для входа по умолчанию
- **Логин:** `admin@logistics.com`
- **Пароль:** `admin123`

## 🔧 Функциональность

### Основные возможности
- **Аутентификация и авторизация** с ролевой моделью
- **Загрузка данных** из Excel файлов
- **Расчет ставок** для различных типов перевозок
- **Комплексный поиск** оптимальных маршрутов
- **Управление пользователями** для администраторов
- **Экспорт данных** в различные форматы

### Типы перевозок
1. **Прямые морские перевозки** - перевозки контейнеров напрямую морем
2. **Прямые железнодорожные перевозки** - перевозки контейнеров напрямую по железной дороге
3. **Комплексные перевозки** (море + железная дорога) - комбинированные перевозки с автоматическим расчетом
4. **Отдельные ставки** по типам транспорта - расчет ставок для каждого типа отдельно

### Особенности комплексных расчетов
- **Динамический расчет** - данные не хранятся в базе, а вычисляются на основе других типов
- **Автоматическое соединение** - система автоматически находит связанные морские и железнодорожные маршруты
- **Конвертация валют** - морские ставки в USD автоматически конвертируются в RUB для сложения с ЖД ставками
- **ВТТ включение** - возможность добавления стоимости ВТТ к комплексным ставкам

## 📊 Базы данных

Система использует PostgreSQL для хранения всех данных:

### Модели данных
- **SeaData** - Морские перевозки
- **RailData** - Железнодорожные перевозки
- **DirectSeaData** - Прямые морские перевозки
- **DirectRailData** - Прямые железнодорожные перевозки
- **TariffData** - Тарифы и дополнительные услуги
- **User** - Пользователи системы

### Особенности хранения
- **JSONB поля** - данные логистики хранятся в формате JSONB для гибкости
- **Автоматическое обновление** - время последнего обновления отслеживается автоматически
- **Подсчет записей** - количество записей сохраняется для быстрого доступа
- **Резервное копирование** - автоматическое создание резервных копий в localStorage

## 🔄 API Endpoints

### Данные
- `GET /api/data/{type}` - Получить данные по типу
- `POST /api/data/{type}` - Сохранить данные

### Аутентификация
- `POST /api/auth/login` - Вход в систему
- `POST /api/auth/logout` - Выход из системы

### Курсы валют
- `GET /api/exchange-rate` - Получить курс ЦБ РФ

## 🛠️ Технологии

- **Frontend:** HTML5, CSS3, JavaScript (ES6+)
- **Backend:** Node.js, Express.js
- **База данных:** PostgreSQL с Sequelize ORM
- **Библиотеки:** XLSX для работы с Excel, bcryptjs для шифрования паролей, JWT для аутентификации

## 🐛 Решенные проблемы

✅ **Исправлена навигация между интерфейсами:**
- Кнопки "Закупщик" и "Менеджер по продажам" теперь открывают интерфейсы в текущей вкладке
- Администратор сохраняет свою роль при переходе между интерфейсами
- Корректный возврат на главную страницу при выходе

✅ **Исправлена система авторизации:**
- Автоматическое перенаправление пользователей на соответствующие интерфейсы после входа
- Пользователи с ролью "sales" автоматически перенаправляются на `interfaces/sales-interface.html`
- Пользователи с ролью "purchaser" автоматически перенаправляются на `interfaces/purchaser-interface.html`
- Отдельные интерфейсы проверяют авторизацию при загрузке
- Обновлены пути перенаправления после реорганизации структуры проекта

✅ **Объяснение сообщения о комплексных расчетах:**
- Сообщение "⚠️ Тип данных 'complex' не загружается из базы данных (комплексный расчет)" - это нормальное поведение
- Комплексные расчеты не хранятся в базе данных, а вычисляются динамически
- Система корректно обрабатывает тип 'complex' и возвращает пустой массив данных
- Комплексные расчеты продолжают работать корректно, объединяя данные из других типов перевозок
