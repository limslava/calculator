# Руководство по настройке PostgreSQL в Amvera

## Создание кластера PostgreSQL в Amvera

### Шаг 1: Создание базы данных
1. На главной странице Amvera выбрать «PostgreSQL»
2. Нажать «Создать базу данных»
3. Задать параметры:
   - **Название проекта**: `calculator-db` (или другое название)
   - **Тариф**: «Начальный» или выше
   - **Имя базы данных**: `logistics_calculator` (не `postgres`)
   - **Имя пользователя**: `calculator_user` (не `postgres`)
   - **Пароль пользователя**: надежный пароль
   - **Размер кластера**: 1 реплика (для начала)
   - **Superuser Access**: активировать (рекомендуется)
   - **Пароль для Superuser**: надежный пароль

### Шаг 2: Подключение к кластеру

#### Доменные имена для подключения:
- **Для чтения/записи**: `amvera-limslava-cnpg-calculator-db-rw`
- **Только для чтения**: `amvera-limslava-cnpg-calculator-db-ro`
- **Для чтения с любой ноды**: `amvera-limslava-cnpg-calculator-db-r`

#### Полный URL подключения:
```
postgresql://calculator_user:password@amvera-limslava-cnpg-calculator-db-rw:5432/logistics_calculator
```

## Настройка переменных окружения в Amvera

### Обязательные переменные:
```
DATABASE_URL=postgresql://calculator_user:your-password@amvera-limslava-cnpg-calculator-db-rw:5432/logistics_calculator
NODE_ENV=production
PORT=3000
JWT_SECRET=your-very-secure-jwt-secret-key-here
```

### Дополнительные переменные:
```
LOG_LEVEL=info
CORS_ORIGIN=*
```

## Подключение через pgAdmin (опционально)

### Развертывание pgAdmin в Amvera:
1. Создать преднастроенный сервис «Утилиты для баз данных» → «pgAdmin»
2. Указать переменные окружения:
   - `PGADMIN_DEFAULT_EMAIL=your-email@example.com`
   - `PGADMIN_DEFAULT_PASSWORD=your-pgadmin-password`

### Настройка подключения в pgAdmin:
- **Host name/address**: `amvera-limslava-cnpg-calculator-db-rw`
- **Maintenance database**: `logistics_calculator`
- **Username**: `calculator_user` (или `postgres` для superuser)
- **Password**: соответствующий пароль
- **SSL mode**: `prefer`

## Бэкапы и восстановление

### Автоматические бэкапы:
- Активировать в настройках кластера
- Хранятся последние 3 бэкапа
- Создаются ежедневно в указанное время

### Ручные бэкапы:
- Создаются по клику «Создать бэкап»
- Максимум 3 ручных бэкапа
- Бесплатно

### Восстановление:
- Восстановление создает новый сервис
- После восстановления обновить URL в проекте
- Пользователи и пароли восстанавливаются автоматически

## Особенности приложения

### Автоматическая инициализация:
При первом запуске приложение автоматически:
- Создает все необходимые таблицы
- Создает администратора (admin@logistics.com / admin123)
- Загружает начальные данные для логистики

### Типы данных:
- **sea** - морские перевозки
- **rail** - железнодорожные перевозки  
- **direct_rail** - прямые железнодорожные перевозки
- **direct_sea** - прямые морские перевозки
- **tariff** - тарифные данные
- **complex** - комплексные расчеты (динамически вычисляются)

### Предупреждение о комплексных расчетах:
Сообщение «⚠️ Тип данных complex не загружается из базы данных» является нормальным поведением - комплексные расчеты вычисляются динамически на основе других данных.

3. Функциональность авторизации

```
GET /health
```
Возвращает статус приложения и timestamp.

## Устранение неполадок

### Ошибка подключения к базе данных:
- Проверить корректность DATABASE_URL
- Убедиться, что кластер PostgreSQL запущен
- Проверить настройки SSL

### Ошибка авторизации:
- Проверить JWT_SECRET переменную
- Убедиться, что она достаточно длинная и безопасная

### Проблемы с производительностью:
- Увеличить размер кластера (количество реплик)
- Настроить параметры пула соединений в config/database.js
