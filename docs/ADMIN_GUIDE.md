# 🔧 Руководство по администрированию

## Восстановление администратора

### Проблема
После исправления кнопки "Назад" администраторская учетная запись `admin@logistics.com` стала определяться как менеджер по продажам (sales) вместо администратора.

### Решение

#### Способ 1: Использование страницы сброса (рекомендуется)

1. Откройте файл [`reset-admin.html`](reset-admin.html) в браузере
2. Нажмите кнопку "Сбросить администратора"
3. После успешного сброса перейдите к основному приложению [`index.html`](index.html)
4. Войдите с данными:
   - **Логин**: `admin@logistics.com`
   - **Пароль**: `admin123`
   - **Роль**: Администратор

#### Способ 2: Ручной сброс через консоль браузера

1. Откройте основное приложение [`index.html`](index.html)
2. Откройте консоль разработчика (F12 → Console)
3. Выполните следующие команды:

```javascript
// Очистка localStorage
localStorage.removeItem('logistics_users');
localStorage.removeItem('current_user');
localStorage.removeItem('sent_emails');

// Создание администратора
const adminUser = {
    id: Date.now().toString(),
    email: 'admin@logistics.com',
    role: 'admin',
    password: btoa('admin123'),
    isActive: true,
    createdAt: new Date().toISOString(),
    lastLogin: null
};

const users = [adminUser];
localStorage.setItem('logistics_users', JSON.stringify(users));

console.log('✅ Администратор восстановлен');
console.log('Логин: admin@logistics.com');
console.log('Пароль: admin123');
```

4. Обновите страницу и войдите с новыми данными

### Проверка восстановления

После восстановления администратора проверьте:

1. Войдите как `admin@logistics.com` / `admin123`
2. Должна отобразиться **панель администратора** с возможностью управления пользователями
3. В консоли браузера должны быть сообщения:
   - `✅ Пользователь авторизован: admin@logistics.com`
   - `🔧 Роль пользователя: admin`
   - `✅ Показана панель администратора`

### Причина проблемы

Проблема возникла из-за конфликта между локальной переменной `currentRole` в [`script.js`](script.js) и глобальной переменной `window.currentRole` в [`auth-ui.js`](auth-ui.js). При исправлении кнопки "Назад" произошло изменение логики работы с ролями, что привело к неправильному определению роли администратора.

### Предотвращение в будущем

Система теперь включает дополнительные проверки:
- Проверка наличия администратора при загрузке пользователей
- Детальное логирование ролей при аутентификации
- Автоматическое создание администратора при его отсутствии

## Исправление проблемы перенаправления из панели администратора

### Проблема
Кнопки "Закупщик" и "Менеджер по продажам" в панели администратора открывали интерфейсы в новой вкладке вместо перехода в текущей вкладке. После перехода в интерфейсы и выхода, система запоминала измененную роль администратора и при следующем входе открывала соответствующий интерфейс вместо панели администратора.

### Решение

#### 1. Исправление функций перенаправления в script.js

**Файл:** [`script.js`](script.js:257-291)

**Исправленные функции:**
- [`redirectToSalesInterface()`](script.js:258-273) - перенаправление в интерфейс менеджера по продажам
- [`redirectToPurchaserInterface()`](script.js:276-291) - перенаправление в интерфейс закупщика

**Ключевые изменения:**
```javascript
// Для администратора не меняем роль, для остальных пользователей обновляем роль
if (currentUser.role !== Auth.USER_ROLES.ADMIN) {
    Auth.updateUserRole(currentUser.id, 'sales');
}
// Для всех пользователей (включая администратора) перенаправляем на отдельный интерфейс
window.location.href = 'sales-interface.html';
```

#### 2. Исправление проверки авторизации в отдельных интерфейсах

**Файл:** [`purchaser-script.js`](purchaser-script.js:37-42)

**Исправленная проверка:**
```javascript
if (!currentUser || (currentUser.role !== 'purchaser' && currentUser.role !== 'admin')) {
    window.location.href = 'index.html';
    return;
}
```

**Файл:** [`sales-script.js`](sales-script.js:1538-1543)

**Исправленная проверка:**
```javascript
if (!currentUser || (currentUser.role !== 'sales' && currentUser.role !== 'admin')) {
    window.location.href = 'index.html';
    return;
}
```

#### 3. Исправление функций выхода из системы

**Файл:** [`purchaser-script.js`](purchaser-script.js:478-491)

**Функция выхода:**
```javascript
function logoutUser() {
    console.log('🔐 Выход из системы менеджера по закупкам');
    
    // Сбрасываем глобальные переменные
    window.currentRole = '';
    window.currentDatabase = '';
    window.uploadedData = null;
    
    // Очищаем localStorage авторизации
    localStorage.removeItem('current_user');
    
    // Возвращаем на главную страницу (index.html)
    window.location.href = 'index.html';
}
```

**Файл:** [`sales-script.js`](sales-script.js:1639-1653)

**Функция выхода:**
```javascript
function logoutUser() {
    console.log('🔐 Выход из системы менеджера по продажам');
    
    // Сбрасываем глобальные переменные
    window.currentRole = '';
    window.currentDatabase = '';
    window.currentCalculationType = '';
    window.uploadedData = null;
    
    // Очищаем localStorage авторизации
    localStorage.removeItem('current_user');
    
    // Возвращаем на главную страницу (index.html)
    window.location.href = 'index.html';
}
```

### Результат

#### ✅ Решенные проблемы:

1. **Перенаправление в текущей вкладке** - кнопки "Закупщик" и "Менеджер по продажам" теперь открывают интерфейсы в текущей вкладке
2. **Сохранение роли администратора** - при переходе администратора в другие интерфейсы его роль не изменяется
3. **Корректный возврат на главную** - при выходе из системы пользователь всегда возвращается на главную страницу
4. **Правильная авторизация** - администратор всегда попадает в панель администратора при входе, независимо от предыдущих переходов

#### 🔧 Технические детали:

- **Роль администратора:** [`Auth.USER_ROLES.ADMIN`](auth.js:5)
- **Проверка роли:** [`currentUser.role !== Auth.USER_ROLES.ADMIN`](script.js:267)
- **Перенаправление:** [`window.location.href`](script.js:272) вместо открытия в новой вкладке
- **Очистка состояния:** [`localStorage.removeItem('current_user')`](purchaser-script.js:487)

3. **Вход как обычный пользователь** → **Переход между интерфейсами** = ✅ Корректная работа
