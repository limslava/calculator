## 🧪 Этап 2: Тестирование с реальными данными

### 2.1 Получить реальные значения для фильтров:
```javascript
// В консоли браузера на странице менеджера
// 1. Получить уникальные линии (carrier)
const uniqueLines = [...new Set(database.sea.map(item => item.carrier).filter(Boolean))];
console.log('Доступные линии:', uniqueLines);

// 2. Получить уникальных агентов
const uniqueAgents = [...new Set([
  ...database.sea.map(item => item.agent).filter(Boolean),
  ...database.rail.map(item => item.agent).filter(Boolean)
])];
console.log('Доступные агенты:', uniqueAgents);

// 3. Получить уникальные терминалы ЖД
const uniqueTerminals = [...new Set(database.rail.map(item => 
  item.тыловойТерминал || item.agent
).filter(Boolean))];
console.log('Доступные терминалы ЖД:', uniqueTerminals);
```

### 2.2 Обновить моковые данные в прототипах:
- Заменить моковые данные в `test-filters-prototype.html` на реальные значения
- Проверить, что автодополнение работает с реальными данными

## 🚨 Дефекты для отслеживания:

1. **Критические:**
   - Фильтры ломают существующую функциональность
   - Ошибки JavaScript при добавлении/удалении фильтров
   - Неправильная фильтрация результатов

2. **Средние:**
   - Медленная работа автодополнения
   - Визуальные артефакты
   - Проблемы с отображением на мобильных

3. **Мелкие:**
   - Неидеальные анимации
   - Незначительные расхождения в отступах
   - Оптимизация кода
